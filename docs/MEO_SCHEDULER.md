# MEO 调度策略接入说明

v1.5 接入用户提供的 `MEO_Project_runnable.zip` 中两份真实训练权重：`spec_w000`（完成率偏好）和 `spec_w100`（精度偏好）。网页启动默认使用完成率偏好，右侧“调度策略”可以切换另一份专家权重、最早完成规则或纯本地。切换会保存本轮记录，并以种子 42 重置；原来暂停则保持暂停。

## 实际执行路径

`SUMO 车辆进入感知区域 → simulation._sense → MeoScheduler.build_graph → NumpyMeoActor.forward → 模式/模型/邻居决策 → reserve_meo_task → 队列与回传 → 原有有界信号门控`。

- 策略网络保留图编码、偏好 FiLM、7 个车道通道、本地/卸载/丢弃三模式、共享模型画像打分器、带掩码的邻居打分器。使用确定性 argmax；不会用最早完成规则替换网络不理想的选择。
- 本地或卸载动作使用选中的 M1–M5 资源档位；计算服务时长为 `serviceTimeS × uniform(0.9,1.1) × compute_gcyc / 0.45`。工作量随机数固定种子。M1–M5 的配置计算量分别为 0.05、0.12、0.45、0.80、1.80 Gcyc。
- 丢弃任务保留任务编号、车辆档案、策略输出和事件，独立计数；不预约队列、不回传、不触发信号。无有效邻居的卸载请求按原环境语义拒绝，保留请求模式与原因，不偷偷改成本地执行。
- 正常任务仍采用每个 RSU 一个非抢占工作线程的预约队列。完成结果返回后才检查信号：匹配当前绿灯、无黄灯、每绿相位最多一次、每次最多 4 秒、总绿灯不超过 55 秒。
- 每项任务的 `policyDecision` 记录专家类型、车道通道、模式 logits、目标、模型资源档位和决策原因；导出配置记录 checkpoint 与推理资产 SHA-256。`GET /api/integration` 可以查看当前策略来源。

## 输入适配与边界

原训练环境为 42 个 RSU、离线 CSV、每秒联合批次准入；当前为唐岛湾 9 个 RSU、实时 SUMO 车辆触发任务、串行预约队列。此次完成的是**训练 actor 到现有演示调度的可执行迁移**，不是原训练环境及论文实验的完整复现，也没有重新训练或证明新地图上的调度优越性。

1. 车道编号末尾的数值映射到 0–6 通道，超范围裁剪；这与原代码解析方式一致，但不意味着对应唐岛湾实测的七种声学环境。
2. 每个 RSU 使用最近 4 个站作为配置通信邻居，按距离和编号排序，填入 12 个邻居槽位，其余掩码关闭。这是演示通信拓扑，距离来自真实地图上的示意设备位置；不是实测无线连通性。
3. 节点特征含按源站保留的待返回任务、对应车道计数、10 秒配置剩余期限、队列工作量、入口车辆计数、上次模型和专家偏好；未采集字段使用明确的演示常量。10 秒值仅作策略特征，当前队列不据此强制超时丢弃。
4. 2048 预算及基于队列的负载是输入代理量，不能称为实际显存测量。链路输入沿用原训练公式，实际传输/回传时长仍由本项目 `SyntheticTransport` 决定；两者不是实测同一设备。
5. 包中的 M1–M5 只是资源与人为精度画像；**没有五个声学识别模型的权重，也没有对播放 WAV 进行分类/定位**。“精度偏好”是训练目标标签，不是本次识别精度实测。真实感知接入继续使用 `docs/MODEL_INTEGRATION.md` 中的接口。
6. 两份专家各自固定偏好 `[0,1]` 和 `[1,0]`，不宣称已有连续可调 Pareto 策略或新增蒸馏权重。

## 推理资产和复现

- `integration/meo_policy.py`：NumPy float32 图 actor 和实时输入适配；运行时不加载 pickle，不需要 PyTorch 或 CUDA。
- `models/meo/manifest.json`：原 actor 源码、配置、checkpoint、导出 NPZ 的哈希和结构；NPZ 只包含 actor 数组，不含训练数据、优化器或 critic。
- `scripts/export_meo_policy.py`：从另行提供的原工程安全导出并比较逐头 logits/argmax；开发复现需 PyTorch、NumPy、PyYAML，普通用户启动不需要这些训练依赖中的 PyTorch/PyYAML。
- `evidence/v1_5_20261008/meo_export_parity.json`：两专家共 104 个图输入、21,840 个动作头 argmax 对照；0 不一致，最大绝对 logits 误差约 0.000199。浮点微差不等于任意输入都能形式化保证同一动作。
- `tests/verify_meo_journey.py`：两专家各 600 秒实际 SUMO 闭环，检查任务、预约、丢弃、回传、信号门控、车辆档案与执行耗时；输出当前版本证据。

固定 Windows 便携运行依赖为 Python 3.12.10、SUMO 1.25.0、NumPy 1.26.4；后者官方支持 Python 3.9–3.12，见 [NumPy 发布说明](https://numpy.org/doc/1.26/release/1.26.4-notes.html)。源码启动器缺少 NumPy 时使用项目私有便携目录，不向用户的系统 Python 安装包。轻量推理限制 BLAS 线程，避免小图推理占满 CPU。

原始压缩包、CSV、论文、训练日志和本地运行数据保留在私有工作区，未进入公开交付。公开内容是适配代码、导出的 actor 权重及来源哈希，不能据此还原或声称拥有原训练集。
